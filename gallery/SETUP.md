vibe1 작품 갤러리(`2026-vibe1/gallery/`)를 바탕으로 만들었습니다.

- 배포 주소: https://greatsong.github.io/2026-ai-leader-training/gallery/
- 올리기 화면 바로 열기(슬라이드 QR용): https://greatsong.github.io/2026-ai-leader-training/gallery/#submit
- 저장소: https://github.com/greatsong/2026-ai-leader-training (GitHub Pages, `main` 가지 루트)

## 2. 다른 갤러리와의 관계

같은 Supabase 프로젝트를 사용하되 테이블과 함수 이름을 따로 사용합니다.

| 과정 | 이름 |
|---|---|
| 서울대 15시간(`web/gallery/`) | `apps`, `feedback`, `increment_likes` |
| 자격연수 4시간(`2026-snui/vibe1/gallery/`) | `vibe1_` 로 시작 |
| 경기도 정보교사 연수(`2026-vibe1/gallery/`) | `vibe1gg_` 로 시작 |
| **이 연수** | **`aileader_` 로 시작** |

`schema.sql`은 `aileader_` 로 시작하는 것만 만들고 고칩니다. 다른 과정의 테이블은 건드리지 않습니다.
브라우저 저장소(localStorage) 키도 `aileader_` 로 시작해서, 같은 `greatsong.github.io` 주소 아래의
다른 갤러리와 섞이지 않습니다.

## 3. 테이블 만들기 (연수 전 1회)

> **실행 기록:** 2026-10-27 운영 DB에 실행했습니다. 공개 키로 테이블 직접 접근이 막히는 것과 화면용 함수 9개만
> 열린 것을 확인했고, 실제 모드 시험(올리기·좋아요·댓글·답글·고치기)을 마친 뒤 시험 글을 지워 테이블은 비어 있습니다.
> 아래 순서는 다시 실행하거나 다른 프로젝트에 옮길 때 사용합니다.

1. Supabase 대시보드에서 프로젝트 `ipcherzsnaevkkjrclvn` 을 엽니다.
   이 프로젝트는 학교 계정 쪽 조직 `greatsong-danggok's Org` 의 `snu-data-2026-gallery` 입니다
   (크롬 '교사·학교' 프로필에서 로그인). greatsong21@gmail.com 계정과 이 컴퓨터의 Supabase CLI에서는 보이지 않습니다.
2. 왼쪽 **SQL Editor** > **New query** 에 이 폴더의 `schema.sql` 전체를 붙여 넣고 **Run** 을 누릅니다.
3. 갤러리 화면을 새로고침해 빨간 안내가 사라지고 "만든 앱 0개 · 풀고 싶은 문제 0개"가 표시되면 끝입니다.

여러 번 실행해도 안전합니다. 이미 올라온 글은 그대로 남습니다.

`schema.sql` 이 만드는 것

- 테이블 5개: `aileader_posts`(글), `aileader_comments`(댓글과 답글), `aileader_likes`(좋아요),
  `aileader_reports`(신고), `aileader_meta`(변경 번호)
- 화면용 함수 9개: `aileader_feed`, `aileader_rev`, `aileader_add_post`, `aileader_edit_post`,
  `aileader_delete_post`, `aileader_toggle_like`, `aileader_add_comment`, `aileader_delete_comment`,
  `aileader_report`
- 내부 함수 3개(화면에서 호출 불가): `aileader_hash`, `aileader_clean`, `aileader_bump_rev`

답글은 `aileader_comments` 에서 `parent_id` 에 원래 댓글 id가 들어 있는 행입니다. 답글은 한 단계까지만 두며,
답글에 다시 답글을 달면 원래 댓글 아래에 `@이름` 을 붙여 이어집니다. 답글이 달린 댓글을 작성자가 지우면
행은 남기고 내용만 비워(`deleted = true`) "지운 댓글입니다"로 표시합니다. 다른 사람의 답글은 지우지 않습니다.
남은 답글까지 모두 지워지면 그 행도 정리됩니다.

실행 뒤 대시보드 **Advisors > Security Advisor** 에 다음 두 항목이 표시될 수 있습니다. 둘 다 의도한 구조입니다.

- RLS는 켜져 있지만 정책이 없는 테이블: 화면이 테이블을 직접 읽거나 쓰지 못하게 일부러 정책을 만들지 않았습니다.
- anon이 실행할 수 있는 security definer 함수: 모든 읽기와 쓰기를 이 함수들이 검사한 뒤 처리합니다.

## 4. config.js

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://ipcherzsnaevkkjrclvn.supabase.co",
  SUPABASE_KEY: "sb_publishable_...",   // 공개용 키
  DB_PREFIX: "aileader_"
};
```

- **service_role(secret) 키는 넣지 않습니다.** 화면에 들어가면 누구나 데이터를 지울 수 있습니다.
- publishable 키는 공개돼도 됩니다. 이 키로는 `aileader_` 함수만 호출할 수 있고, 함수가 본인 여부와 입력 형식을 검사합니다.
- 주소와 키를 비우면 체험 모드로 바뀝니다.

## 6. 운영 수칙

- **연수 전날과 당일 아침에 1회씩 접속합니다.** Supabase 무료 요금제는 1주일 동안 활동이 없으면 프로젝트를
  일시 중지합니다. 중지되면 대시보드에서 직접 복원해야 하고 복원에 몇 분이 걸립니다.
- **진행자 관리는 Table Editor 에서 합니다.** 별도 진행자 화면은 없습니다.
  - 숨겨진 글·댓글 다시 보이기: `aileader_posts` 또는 `aileader_comments` 에서 `hidden` 을 `false` 로 바꿉니다.
  - 글·댓글 지우기: 해당 행을 지웁니다. 글을 지우면 그 글의 댓글·답글·좋아요·신고도 함께 지워지고,
    댓글 행을 지우면 그 댓글에 달린 답글도 함께 지워집니다. 답글은 남기고 댓글만 가리려면 행을 지우지 말고
    `hidden` 을 `true` 로 바꿉니다("신고가 모여 숨겨진 댓글입니다"로 표시).
  - 신고 내역: `aileader_reports` 에서 봅니다.
  - Table Editor 에서 고친 내용도 참가자 화면에 5초 안에 반영됩니다.
- **자동 제한(schema.sql 에서 숫자를 바꿀 수 있습니다)**
  - 한 브라우저가 올릴 수 있는 글 20개, 댓글은 1분에 10개
  - 연수 전체 글 500개, 댓글 3,000개
  - 신고 3건이면 자동 숨김(`aileader_report` 함수의 `c_hide_at`)
- **금지어**: `app.js` 맨 위 `BANNED_WORDS` 배열에 단어를 추가합니다. 화면에서만 거르므로 완전한 차단은 아닙니다.
- **장애 시 대체**: 갤러리가 열리지 않으면 패들렛 같은 예비 게시판에 앱 주소를 남기게 안내하고 진행합니다.

## 7. 로그인 없이 좋아요와 '내 글'을 구분하는 방식

- 갤러리를 처음 연 브라우저는 임의 열쇠(16진수 32자)를 만들어 localStorage 에 저장합니다.
- DB에는 열쇠의 sha256 해시만 저장하고, 화면으로 내보내지 않습니다.
- 같은 열쇠로는 글 하나에 좋아요를 한 번만 누를 수 있고, 그 열쇠로 올린 글과 댓글만 고치거나 지울 수 있습니다.

한계

- 다른 브라우저, 다른 기기, 시크릿 창은 다른 사람으로 취급합니다. 같은 사람이 브라우저를 바꾸면 좋아요를
  한 번 더 누를 수 있고, 이전 브라우저에서 올린 글은 고칠 수 없습니다. 이때는 진행자가 Table Editor 에서 고칩니다.
- 사이트 데이터를 지우면 열쇠가 사라져 내 글을 고칠 수 없게 됩니다.
- API를 직접 호출하며 열쇠를 바꿔 좋아요를 부풀리는 것은 막지 못합니다. 15명 규모 연수에서는 감수할 수 있는 수준으로 판단했습니다.

## 8. 공개 안내

- 표시 이름, 글, 댓글, 앱 주소는 갤러리 주소를 아는 누구나 볼 수 있습니다.
- 학교명, 연락처, 학생 개인정보를 받는 칸은 없습니다. 올리기 화면에도 적지 말라는 안내를 넣었습니다.
- 실명 대신 표시 이름 사용을 권합니다.
